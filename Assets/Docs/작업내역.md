## 2. 작업 순서 (단계별 기록)

### 2-1. 프로토타입 시작
- 원본 기획서 `guild_receptionist_design.md`를 읽고 첫 프로토타입 제작
- **문제**: 프로젝트가 한글 경로(`문서`) 아래 있어서 Unity ApiUpdater가 `FileNotFoundException`을 내며 컴파일 불가 → 프로젝트를 `C:\Unity\GQProject`로 옮김
- 첫 버전은 UI를 코드로 생성 → **사용자 지적**: "하이어라키에서 보이게, 코드로 만들지 말 것" → 모든 UI를 씬 오브젝트로 다시 구성

### 2-2. 레이아웃 방향 결정
- '파피용/려권 내라우'식 책상 레이아웃 → **사용자 요청**으로 '칼바레인'식(가운데 큰 캐릭터)으로 전환
- 캐릭터가 작다는 지적 → 낮 화면 왼쪽 절반에 큰 캐릭터 + 대화창, 오른쪽에 책상

### 2-3. 기획서대로 핵심 규칙 구현
- 귀환 모험가가 **증거물**을 가져오고, 게시본 기입란과 대조해 완료 심사
- 길드 카드를 **신분증처럼** 표시 (초상 · 등급 테두리 · 인장 · 번호)
- **위조 검사**는 하루 지날 때마다 하나씩 해금 (테두리 → 인장 → 초상 → 번호)
- **수수료 고정 15G/건** (사용자 결정)
- **잘못된 기입으로 성공한 의뢰**: 일단 보상·수수료는 받고, 밤 결과 화면에서 "잘못된 의뢰 성공 패널티" −15G · 평판 하락 (사용자 결정)
- **길드 평판** 시스템 추가, 상단 시계 가독성 개선

### 2-4. '게임다운 느낌' 개선
- 길드 카드 · 의뢰서 · 증거물을 **드래그**해서 옮길 수 있게 (`DraggableDocument`)
- 몬스터 도감은 덮인 책을 클릭하면 펼쳐지고 넘겨 보는 방식
- 이미지는 전부 데이터 에셋의 Sprite 필드로 교체 가능하게

### 2-5. 객체 지향 구조로 재작성
- 상태는 private set + 메서드, 종류별 동작은 다형성
  - `Visit`(추상) → `ApplicationVisit` / `ReturnVisit` / `ChatVisit` (이후 `UrgentVisit` 추가)
  - `IForgery` → 테두리 · 인장 · 초상 · 번호 위조
  - `ITempRule` → 축제 · 수배 · 전염병 규칙

### 2-6. Claude 추가 기획 (세계관 · 캐릭터 · 몬스터)
- 마을 '로웰', 최종 위협 '숲의 왕', 네임드 6명(루루 · 니아 · 올리버 · 레온 · 세실리아 · 바르톨), 선배 마르타, 길드장 그라함
- 몬스터 6종 추가 → 총 13종 (헷갈리는 짝 설계)
- 네임드별 대사 · 개인 이벤트 3개(호감도 55/70/85)
- 모든 내용을 `기획_추가안_Claude.md`에 [Claude 제안] 표기로 기록
- 네임드 6명의 **상세 캐릭터 기획서** 작성 (`Characters/01~06`, 관계도 `00_관계도_인덱스.md`)

### 2-7. 씬 분리
- 한 씬 → `Core` / `Night` / `Day` 세 씬으로 분리 (사용자 요청)
- Core가 시작할 때 Night · Day를 Additive로 불러와 View를 찾아 연결
- 어느 씬에서 Play해도 Core부터 시작하는 에디터 스크립트 (`PlayFromCore.cs`)

### 2-8. 스크립트 · 에셋 연결 끊김 사고
- 프로젝트 이동 뒤 ScriptableObject 에셋의 스크립트 연결이 끊어져 NullReference 발생
- 원인: 한 파일(`GameData.cs`)에 ScriptableObject 여러 개 → 파일마다 하나씩 분리하고 에셋 40개의 `m_Script` 참조를 복구
- 같은 이유로 `UIEffects.cs`를 컴포넌트별 파일로 분리
- **규칙으로 고정**: MonoBehaviour · ScriptableObject는 클래스 이름과 같은 파일에 하나씩

### 2-9. 5주 콘텐츠 · 평판 효과 · 사망 판정 · 연출
- 주차 데이터 5개: 1주차 평화 / 2주차 **수확 축제** / 3주차 **수배 주간** / 4주차 **전염병 주간** / 5주차 **숲의 왕**
- 평판 효과: 평판이 높을수록 높은 등급 모험가가 찾아오고, 주말 습격 참가율이 올라감
- 3주차부터 **사망 판정**, 3주차 **바르톨 원정** (동행자 선택 · 누적 피로 · 호감도로 생사)
- 낮 창구 업그레이드: 신고 종 · 수배서 게시판 · 임시 규칙 배너 · 떠오르는 글 · 책상 흔들림
- 자동 생성 의뢰 (몬스터 단서 + 의뢰인 말투: 과장/축소/정확/착각)
- 밸런스를 세 가지 플레이 모델(완벽 · 보통 · 부주의)로 자동 테스트해 조정

### 2-10. 추천 순서 다섯 묶음 (이번 작업)
사용자가 "추천 순서대로 해보자"로 승인한 순서:
1. **세이브 · 타이틀 · 재도전**
2. **밤 루틴**: 승급 심사 · 게시판 구성(칸 제한 → 이후 사용자 결정으로 제거, 2-12 참고) · 밤 상점 · 성공 보너스
3. **낮 창구**: 길드 홀 지명(수당 흥정) · 긴급 의뢰
4. **이벤트**: 주차 조건 개인 이벤트 · 랜덤 사건 · 레온 위조 중단
5. **사운드 · 엔딩**: 효과음/BGM · 주차별 배드 엔딩 · 엔딩 도감

### 2-11. 이번 작업 뒤 사용자 피드백 반영
- "선배가 검토해서 넣는다는 설정으로 자동 의뢰를 넣으면 되지" → **밤마다 선배 의뢰 2건 추가**, 게시판 칸이 실제로 모자라게 됨
  - 선배 의뢰를 보류한 채 기한이 끝나면 **이웃 길드로 넘김** (평판 그대로, 위험도 +2). 처음 버전처럼 −3 평판을 주면 하루 −6~−9로 너무 가혹했음
- "지명 수당이랑 성공 보너스도 넣긴 해야지" → **낮에 그 자리에서 자금에서 지급** (모자라면 못 함). 밤 결과엔 "(낮에 지급)"으로 기록만
- "매일매일 지명으로 부릴 수 있는 건 아니지?" → **홀에 나와 있는 사람이 매일 무작위** (네임드 각 35%, 이름 없는 모험가 4명) + **하루 지명 2회 제한**
- "바르톨은 그냥 둬" → 원정 조건 그대로
- "개인 이벤트는 나중에" → 5주차 결전 이벤트 등은 보류

### 2-12. 게시판 칸 제한 제거 (사용자 결정)
- "게시판에 붙이는 거 없애자, 다 붙이고 다 처리해야 하는 걸로" → 칸 제한 · 보류함 · 게시판 확장(상점) 제거. 2-11의 "이웃 길드로 넘김" 규칙도 함께 제거
- "주차가 갈수록 자동 의뢰 개수도 늘리고" → 선배 의뢰 1주차 1 · 2주차 2 · 3주차 3 · 4주차 3 · 5주차 4건
- 밤 마무리 화면은 "내일 게시판"(확인 + 상점)으로 바뀜

## 3. 현재 게임 흐름

```
타이틀 (이어하기 · 새 게임 · 엔딩 도감 · 종료)
 └ 프롤로그
   └ [매주]
      주 시작: 자동 저장 → 주차 전환 화면 → 주차 인트로
      [평일 4일]
        밤: 개인 이벤트 → 랜덤 사건 → (원정) → 그날 스토리 → 승급 심사
            → 의뢰서 작성 → 내일 게시판(+선배 의뢰, 전부 게시, +상점)
        낮: 창구 영업 (수주 신청 · 귀환 보고 · 잡담 · 긴급 의뢰 · 길드 홀 지명)
        마감: 판정 · 사망 · 기한 · 정산 → (추모) → 오늘 결과
      주말: 습격 → 주간 정산(신규 모험가) 
   └ 5주차 습격 결과 → 굿 / 씁쓸 엔딩 → 결산 → 타이틀
   └ (길드장 구원을 쓴 뒤 두 번째 습격 실패) → 주차별 배드 엔딩 → "n주차 처음부터 / 처음부터 / 타이틀"
```

## 4. 시스템별 정리

### 4-1. 밤 — 의뢰서 기입
- 의뢰인이 쓴 의뢰서를 읽고 도감에서 몬스터를 골라 **대상 · 수량 · 권장 등급 · 필수 역할**을 기입
- 기입이 틀리면: 모험가가 실패하거나, 성공해도 밤 정산에서 패널티 (−15G · 평판 −5)
- 파일: `Night/NightShift.cs`, `Views/NightView.cs`, `Services/QuestGenerator.cs`

### 4-2. 내일 게시판 · 선배 의뢰
- **칸 제한 · 보류 없음** (사용자 결정): 내가 쓴 의뢰서 + 선배가 검토한 의뢰가 **전부 게시**되고, 낮에 **전부 처리**해야 한다
- 선배 의뢰 수는 주차가 갈수록 늘어남: 1주차 1 · 2주차 2 · 3주차 3 · 4주차 3 · 5주차 4 (`GameConfig.seniorQuestsByWeek`). 기입은 선배가 정답대로
- 기한 초과는 누가 쓴 의뢰든 평판 −3, 위험도 +5
- 이 화면(`BoardSetupView`, 제목 '내일 게시판')은 확인용 목록 + 밤 상점 버튼 + '창구 열기'
- 파일: `Views/BoardSetupView.cs`, `GuildGame.AddSeniorQuests()`, `Counter.Close()`

### 4-3. 승급 심사
- 레벨 또는 실적 중 하나라도 기준에 닿으면 신청 (하룻밤 최대 2명, 첫날 밤 제외)
- 기준: 동→은 레벨 6 + 실적 3 / 은→금 레벨 12 + 실적 6 (`GameDatabase.promotionLevel / promotionRecord`)
- 적격 승급 +6 / 적격 보류 −8 / 미달 승급 +10(억지 승급: 판정 실력은 한 단계 아래) / 미달 보류 −2
- 레벨: 성공 +1, 대성공 +2
- 파일: `Services/PromotionBoard.cs`, `Views/PromotionView.cs`, `Adventurer.TrueRank`

### 4-4. 밤 상점
| 시설 | 가격 | 등장 | 효과 |
|---|---|---|---|
| 돋보기 | 120G | 1주차 | 영업 시간 +20초 |
| 모집 전단 | 40G (매주) | 1주차 | 주간 정산 신규 모험가 +2, 평판 +2 |
| 증거물 저울 | 180G | 2주차 | 귀환 보고서에 기입 일치 여부 표시 |
| 휴게실 | 150G | 2주차 | 부상 회복 2배, 잡담 호감도 2배 |
- 파일: `Services/FacilityShop.cs`, `Views/ShopView.cs`, 데이터 `GameDatabase.facilities`

### 4-5. 낮 창구
- **수주 신청**: 규정 1~3 · 위조 · 임시 규칙 검사 → 승인/거절 (수배 주간엔 신고 종)
- **귀환 보고**: 증거물 대조 → 완료 승인 / 반려 / **완료 승인 + 보너스**(10G 즉시 지급, 호감도 +6)
- **잡담**: 게시판이 비면 네임드가 들름
- **긴급 의뢰**: 2주차부터 하루 40%, 영업 35% 시점에 전령 도착. 보수 1.5배, 오늘 하루 기한. 놓치면 위험도 +10, 평판 −3
- **길드 홀 지명**
  - 홀에 나와 있는 사람: 매일 무작위 (네임드 각 35%, 이름 없는 모험가 4명)
  - 하루 2회 (`nominationsPerDay`), 지명 12초 · 흥정 6초의 영업 시간 소모
  - 수당 = 10 + (의뢰 등급 − 본인 등급 + 1)×10 + 욕심×20 + 보수×5% − (호감도−50)×0.2
  - 흥정 성공(25% + 호감도/150) → 절반 / 실패 → 호감도 −4, 그날 지명 불가
  - 수당은 즉시 지급, 자금이 모자라면 불가. 지명도 규정 검사 대상
- 네임드 방문: 수주 신청자는 40% 확률로 네임드 (`namedVisitChance`), 성격(욕심 · 위조 성향)대로 의뢰를 고름
- 파일: `Day/Counter.cs`, `Day/Visit.cs`, `Day/UrgentVisit.cs`, `Day/Nomination.cs`, `Views/DayView.cs`, `Views/NominationView.cs`

### 4-6. 주말 습격
- 습격 규모 = 마을 위험도 + 주차 기본값(20 · 32 · 48 · 64 · 110)
- 방어력 = 쉬고 있는 모험가(등급 · 호감도 · 평판 참가율) + 호감도 70↑ 네임드 보너스 + 각성 보너스 + (5주차) 니아 봉인의 열쇠
- 완벽 / 아슬아슬 / 실패. 첫 실패는 길드장 그라함 구원(−50G, 평판 −10), 두 번째 실패는 배드 엔딩
- 파일: `Services/RaidResolver.cs`

### 4-7. 이벤트
- 개인 이벤트: 호감도 55/70/85 기본 3개씩 + 주차 조건 이벤트 9개 (`PersonalEvent.minWeek`)
- 레온은 70 이벤트 뒤 위조 카드를 쓰지 않음 (`stopsForgery`)
- 랜덤 사건 9종, 한 판에 한 번씩, 주당 최대 2개 (`GameDatabase.randomEvents`)
- 파일: `Adventurer.PendingEvent`, `Services/RandomEvents.cs`

### 4-8. 세이브 · 엔딩
- 매주 첫날 밤 자동 저장 `persistentDataPath/save.json` (한 칸). 엔딩을 보면 삭제

## 9. 발생했던 문제와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| 컴파일 불가 | 한글 경로에서 ApiUpdater 오류 | 프로젝트를 `C:\Unity\GQProject`로 이동 |
| 에셋 NullReference | 한 파일에 ScriptableObject 여러 개 → 이동 후 스크립트 참조 끊김 | 클래스별 파일 분리, `m_Script` 복구, 규칙화 |
| `??` 연산자가 Unity 오브젝트에서 오작동 | Unity의 가짜 null | `TryGetComponent` / 명시적 null 비교 |
| 테스트 중 플레이 모드가 멈춤 | 에디터 포커스가 없으면 프레임 정지 | 일시정지 후 `EditorApplication.Step()`으로 진행 |
| 플레이 중 씬 수정 예외 | 플레이 모드에서 씬 저장 시도 | 씬 수정 전 반드시 플레이 모드 종료 |
| 습격이 너무 쉬움 | 초기 수치 | 기본 규모 20·32·48·64·110, 신규 모험가 1 + 평판/34로 조정 |
| 결과 미리 노출 | 위험도 변화가 판정 직후 표시 | 귀환 보고 때 반영 |
| 게시판 칸이 무의미 | 의뢰 수가 칸보다 적음 | 선배 의뢰 2건/밤 추가 |
| 보류 의뢰 벌점 과다 | 선배 의뢰까지 −3 평판 | 선배 의뢰는 이웃 길드로 넘김(위험도 +2) |
| (이후) 칸 제한 자체를 제거 | 사용자 결정: 전부 게시 · 전부 처리 | 선배 의뢰 수를 주차별로 늘림 |
| 테스트 중 오디오 채널 부족 경고 | 12배속에서 효과음 누적 | 같은 효과음 0.05초 이내 중복 재생 방지 |

## 11. 사용자가 내린 결정 모음
- UI · 오브젝트는 코드 생성 금지, 하이어라키에서 수정 가능하게
- 칼바레인식 레이아웃, 큰 캐릭터
- 수수료 15G 고정, 잘못된 기입 성공은 밤 정산에서 −15G + 평판 하락
- 위조 검사는 하루에 하나씩 해금
- 평판 → 높은 등급 방문 · 습격 참가율 상승
- 씬 3분할 (Core / Night / Day)
- 객체 지향 구조
- 폰트는 일단 보류
- 추천 순서 다섯 묶음 진행
- 선배가 검토해 넣는 자동 의뢰로 게시판을 채움
- 지명 수당 · 성공 보너스는 실제로 지급
- 바르톨 원정 조건은 그대로
- 추가 개인 이벤트(5주차 결전 등)는 나중에
- 게시판 칸 제한 없음: 전부 게시하고 전부 처리. 선배 의뢰는 주차가 갈수록 증가

Claude Code의 **대화 기록은 이 컴퓨터(`C:\Users\<사용자>\.claude\`)에만 저장**되고 git으로 옮겨지지 않습니다.

- 게임 세이브(`AppData/LocalLow/.../save.json`)와 엔딩 도감(PlayerPrefs) — 테스트용이라 필요 없음
- `Library/`, `Temp/`, `Logs/`, `UserSettings/` — Unity가 다시 만듦

### 새 컴퓨터 준비 순서
1. **Unity 6000.6.3f1** 설치 (Unity Hub)
2. GitHub Desktop으로 `junanimon/GQProject`를 clone — **경로에 한글이 없는 곳**(예: `C:\Unity\GQProject`). 한글 경로에서는 Unity ApiUpdater 오류로 컴파일이 안 됨 (9장 참고)
